# G-Partner

Адаптивный магазин электротранспорта с доставкой по всей России: сайт, Telegram Mini App и кабинет владельца с реальной загрузкой товаров.

**[Руководство по решению и запуску на BotHost](docs/STORE-LAUNCH-2026.md)**

## Что работает

- Публикация товаров из CRM, фото, цена, наличие и характеристики.
- Поиск, фильтры типа/прав/цены/наличия, сортировка, страницы моделей.
- Сроки доставки по семи федеральным округам с базой городов и отдельная зона оплаты.
- Воронка на главной: типы транспорта, товары, подборки, шаги покупки и канал со скидками.
- Избранное, сравнение до трёх моделей, корзина и гостевая заявка.
- Вход владельца `/admin`, черновики, редактирование, настройки магазина и заявки.
- SQLite и фотографии в постоянной папке; серверные сессии, CSRF, проверка загрузок.
- Серверные страницы каталога и гайдов, schema.org Product, sitemap и открытые фиды для поисковиков и ИИ.

[Сроки по округам, выбор города и зона оплаты](docs/DELIVERY-ZONES-AND-PAYMENT.md) · [Воронка главной и канал со скидками](docs/HOME-FUNNEL.md)

Каталог изначально пуст: никаких выдуманных товаров, цен и гарантий. После публикации в CRM модель появляется на сайте. Приём заявок по умолчанию выключен: сначала владелец должен заполнить контакты и сведения о продавце. Онлайн-оплата, касса, автоматическая доставка и уведомления менеджеру не подключены.

## BotHost

Выбрать «Использовать собственный Dockerfile», ветку `main`. Корневые `main.py` и `index.py` сохранены. Бот и HTTP работают одним Python-процессом.

Задать секреты `BOT_TOKEN`, `MINI_APP_URL`, `PUBLIC_ORIGIN`, `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH` (или `ADMIN_PASSWORD`). Пароль не хранится в GitHub. `python scripts/admin_password.py` позволяет безопасно получить хеш.

Партию товаров можно завести не вручную: `python scripts/import_catalog.py https://адрес-магазина docs/catalog-kugoo.json` создаёт карточки по JSON-файлу и загружает фотографии из `photo_files` через CRM. Подготовлены четыре Kugoo с двумя ракурсами каждый. Новые карточки остаются черновиками; у существующих заполняются только пустые галереи, остальные данные сохраняются. `--dry-run` проверяет локальные файлы без входа и записи. [Фотографии, источники и порядок загрузки](docs/KUGOO-PHOTOS.md).

Вход можно сохранить на личном устройстве; удаление товара доступно прямо в списке CRM с подтверждением. [Сроки сессий, фотографии и управление карточками](docs/ACCOUNT-AND-CATALOG.md).

`DATA_DIR=/app/data` — постоянное хранилище BotHost. Проверить сохранение данных после пересборки до загрузки реального ассортимента. `COOKIE_SECURE=true`, HTTPS, порт из `PORT` (по умолчанию 8000). Проверка сервера: `/health`.

Статика собирается в `/opt/magoleg/public`, runtime в `/opt/magoleg/runtime`, чтобы монтирование исходников в `/app` не скрывало готовую сборку.

## Поисковики и ИИ

Сервер отдаёт содержательный HTML без выполнения JavaScript. Публичные страницы видны и человеку, и роботу; отдельного скрытого текста или подмены по User-Agent нет. Цена, наличие и характеристики берутся из той же SQLite-базы, что `/api/products`:

- `/catalog` и `/catalog/{id}/{название}` — индексируемый каталог и карточки с Product/Offer JSON-LD;
- `/guides` — практические гайды и динамические подборки из опубликованного каталога;
- `/sitemap.xml` и `/robots.txt` — обнаружение страниц;
- `/ai/products.json` и `/llms.txt` — компактное описание каталога для систем, которые умеют их читать;
- `/merchant-feed.xml` — товарный XML-фид с ценой и наличием.

На продакшене `PUBLIC_ORIGIN` — рабочий домен магазина, сейчас `https://g-partner.store` (можно перечислить оба домена: `https://g-partner.store,https://g-partner.ru`). После выкладки добавьте домен в Google Search Console и Яндекс Вебмастер, укажите `/sitemap.xml`; полученные токены можно положить в `GOOGLE_SITE_VERIFICATION` и `YANDEX_VERIFICATION`. Товарный фид подключается отдельно в кабинете товарной системы. Подробный чек-лист: [индексация сайта и каталога](docs/SEO-AND-AI-DISCOVERY.md). `PUBLIC_ORIGIN` принимает несколько адресов через запятую; пустое значение оставляет возврат из банка на тот домен магазина, который открыл покупатель. Карта пунктов выдачи включается ключом СДЭК: [виджет ПВЗ](docs/CDEK-PVZ-WIDGET.md).

## Разработка и проверки

Node 24 LTS и Python 3.13 рекомендуются для совпадения с контейнером.

```sh
cd apps/mini-app
npm ci --ignore-scripts
npm test
npm run build
```

Из корня репозитория:

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests
```

Для локального сервера: `WEB_ONLY=true`, `COOKIE_SECURE=false`, `PUBLIC_ORIGIN=http://127.0.0.1:8000`, `STATIC_DIR=apps/mini-app/dist` и отдельная тестовая `DATA_DIR`, затем `python main.py`. `.env.example` — справочник переменных; автоматическая загрузка `.env` не выполняется. Vite dev проксирует API на порт 8000.

## Основные модули

- `src/StoreApp.tsx` внутри mini-app — разделение публичного сайта и CRM.
- `src/storefront/` — покупательские страницы, данные и сценарии.
- `src/storefront/delivery-zones.ts` — округа, города и ориентировочные сроки доставки.
- `src/storefront/Payment.tsx` — способы расчёта, порядок заказа и документы покупателя.
- `src/storefront/Home.tsx` — воронка главной страницы и приглашение в канал со скидками.
- `src/admin/` — кабинет владельца.
- `src/components/StoreHero.tsx` — первый экран и GSAP motion по правилам HyperFrames.
- `store_api.py` — авторизация, SQLite, изображения и заявки.
- `seo_pages.py` — серверный HTML, структурированные данные и публичные фиды.
- `scripts/backup_store.py` — консистентный backup базы и фото.
- `.github/workflows/verify.yml` — frontend/backend тесты и Docker build.

Старые `App.tsx`/`MobileStorefront.tsx` сохранены как предыдущие реализации, но не являются точкой входа. Прежние документы о mock-версии исторические; актуальное руководство — `docs/STORE-LAUNCH-2026.md`.
