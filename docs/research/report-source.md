# G-Partner: исследовательская основа реализации

Дата доступа: 6 сентября 2026. Аудитория: владелец магазина электротранспорта
в Большом Сочи. Решение: витрина и защищённый кабинет, размещаемые на BotHost.
Запрос пользователя: актуальные технологии, премиальный сдержанный дизайн,
облегчение выбора, реальная загрузка товаров. Figma не используется.

## Прямой вывод

Нет доказанного «лучшего в мире» стека или дизайна с гарантированной выручкой.
Для этого проекта рационально сохранить современную React-витрину и Python-сервер,
заменить заглушки реальными данными, уменьшить неопределённость при выборе,
защитить кабинет и проверить работу на телефоне. Локальная SQLite подходит для
одного экземпляра приложения при наличии постоянного диска. Это не архитектура
для бесконтрольного горизонтального масштабирования.

## Технологии: наблюдение и решение

Через официальный npm registry проверены latest-теги: React **19.2.8**, Vite
**8.2.2**, TypeScript **7.0.2**, GSAP **3.15.0**, Three.js **0.185.1**, Tailwind CSS
**4.3.3**. Проверка командой `npm view <package> version` на дату исследования;
версии не гарантированно остаются последними после этой даты. React docs показывают
семейство 19.2, а список патчей может отставать от npm.

Выбран React/Vite/TypeScript из уже работающего проекта; GSAP добавлен точно
зафиксированной зависимостью. CSS Grid, flex, clamp, медиазапросы и переменные
достаточны для интерфейса. Tailwind не добавлен ради косметической миграции.
Three.js не добавлен: у магазина нет проверенных 3D-моделей, а вращение сцены
не решает поиск и покупку. Node 24 LTS используется только для сборки;
финальный контейнер — Python 3.13, aiohttp 3.14.3, aiogram 3.31.0,
Pillow 12.3.0 и стандартная SQLite.

## Дизайн и конверсия

База — антрацит #121214, графит #1E1E22, платиновый текст #E4E6EB,
оранжевые действия #FF6B00. Montserrat 700/800 для заголовков, Inter для текста
и чисел, локальные файлы шрифтов. Это фирменное решение под запрос пользователя,
а не утверждение о «научно самом дорогом» стиле. Модные стеклянные панели,
декоративные иконки, тяжёлые WebGL-эффекты и гигантские пустые карточки отвергнуты.

Исследования Baymard поддерживают явный поиск с кнопкой отправки, понятные
категории, видимые применённые фильтры и контекстные ошибки. Для технических
товаров важны сопоставимые параметры и полная страница товара, а не дополнительное
модальное превью. Сравнение на ПК полезно; приоритет на телефоне — качество
списка и видимость характеристик. Эти выводы основаны преимущественно на США/Европе;
локальная конверсия покупателей Сочи не измерена.

Первый экран не скрывается до завершения анимации. Кейс Nuvemshop объясняет,
как переходы первого баннера задерживали определение LCP. Опубликованные +8,9%
к session-to-paid-order относятся к сравнению одного бразильского набора магазинов
между январём 2025 и январём 2026, а не к контролируемому тесту нашего сайта.
Поэтому это ориентир направления, не прогноз G-Partner.

## Структура пользовательского пути

1. Один логотип, магазин и город, рекламное фото, заметный переход в каталог.
2. Поиск и текстовые категории транспорта; фильтр по правам только по проверенным
   сведениям конкретной модели.
3. Опубликованные товары из CRM: фото, цена, наличие, одинаковый порядок параметров.
4. Страница модели: описание и все введённые характеристики; избранное, сравнение,
   корзина. Нет выдуманных отзывов, «осталось 2 штуки», скидок и гарантий.
5. Корзина: количество, удаление, сумма товаров, отдельное пояснение доставки.
6. Гостевая заявка: имя, контакт, необязательный комментарий, согласие; сервер
   проверяет товары и цену, сохраняет заявку и возвращает её номер.
7. CRM владельца: обработка заявки; подтверждённая продажа остаётся реальным
   бизнес-процессом, не подменяется надписью «оплачено» на сайте.

Рекомендуемая воронка: поиск → товар → корзина → сохранённая заявка → фактическая
продажа. Сторонняя аналитика и передача персональных данных внешнему ИИ не включены.
MCP используется для работы разработчика с браузером, а не как публичный канал
администрирования. Будущая ИИ-помощь должна иметь только чтение опубликованного
каталога и явное подтверждение действий. Без ключей/API и реальных данных такая
интеграция не объявляется готовой.

## Поиск, пробелы, граница остановки

Выполнены ограниченные волны: версии React/Vite/GSAP/Three/Tailwind/Node; чтение
официальных релизов и npm; оригинальные исследования Baymard и web.dev;
follow-up по фильтрам, сравнению и модальным превью; OWASP и SQLite для архитектуры.
Наиболее важные выводы по первому экрану, мобильному поиску, паролям и Node
повторно проверены координатором. Независимая ветка собрала CRO-источники.

Не найдено доказательств гарантированной выручки или лучшего визуального стиля;
точные адрес/контакты/реквизиты, настройки конкретного экземпляра BotHost,
тариф и данные реальных продаж не предоставлены. Документация BotHost позволила
уточнить постоянный путь `/app/data` и вынести runtime из монтируемого `/app`.
Дальнейший широкий поиск
не меняет выбранную архитектуру: следующий источник истины — собственная
аналитика после запуска. Необходимы реальные реквизиты, резервное копирование,
проверка условий обработки данных и хостинга перед открытием заявок.
